## 5) 본 것만 (추정·제안 금지)

- **가게 검색은 검색어마다 승자가 갈린다.** 넓게 걸리는 카페·학원(트라이그램 후보 184,924행)은 30개 구 전부 off 가 4~20배 빠름(on 220~290ms → off 12~78ms). 반대로 좁게 걸리는 편의점·스타벅스·미용실·공인중개사(구 안 최다 몇백~몇천행)는 30개 구 대부분 off 가 1.0~10.7배 느림(최악: 강남 편의점 1.0ms→10.6ms, 마포 편의점 0.9ms→6.5ms). 같은 함수·같은 플래그인데 검색어 선택도에 따라 승패가 뒤집힌다.
- **건물 검색은 빌딩·상가·타워 3종은 30개 구 전부 off 가 이긴다**(on 370~460ms의 BitmapOr+Recheck → off 200~300ms 의 idx_msp_pnu 조인 또는 building Seq Scan). **플라자만 정반대로 off 가 최대 296배 느리다**(on 0.7~1.4ms → off 192~260ms, 30개 구 전부). md5 비교로 세 결과가 동일함을 확인했다.
- **off 가 켜지면 GIN(trgm) 색인(idx_mpsn_names·idx_msp_road_key·idx_msp_jibun_key·idx_building_nm_key)은 전부 Seq Scan 으로 떨어진다** — EXPLAIN 상에서 off 모드는 30개 구 어디서도 이 GIN 색인들을 Bitmap Index Scan 으로 쓰지 않았고, 대신 idx_mpsn_sigungu(가게, btree)나 building/mv_search_parcel Seq Scan(건물)으로 대체됐다. 플라자 off 가 항상 192ms 근방인 것도 이 Seq Scan on building(242,631행) 고정비용 때문이다.
- **결과 동일성은 600칸(가게 360 + 건물 240) 전부 md5 일치 — 불일치 0건.** bitmapscan on/off 는 속도만 바꾸고 정답을 바꾸지 않는다.
- **search_scope 는 다른 함수다** — 표본 3개 구(강남·중구·대전동구) 전부 on 이 760~900ms 로 search_stores/search_buildings 의 on 보다도 느리고, off 는 393~549ms(idx_msp_pnu 또는 building Seq Scan)로 늘 더 빠르다. **전국(sigungu 미지정) 빌딩·타워도 off 가 더 빠르다**(on 396~400ms → off 268~324ms) — district 범위와 같은 방향.
