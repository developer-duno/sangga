## Phase 3 선행 — 실거래 수집·적재 ✅ (2026-08-08 새벽, 계획보다 앞당김)

| `collect_transactions.py` | API → raw JSONL. 이어받기(`collect_progress`, collector=`rtms_commercial`)·일 예산·안전 종료·raw 원자성. 테스트 52개 |

**§5.6의 빈 지표 2개를 채웠다** (지번 공개 구간 2024-01~ 기준):

## 2026-08-08 저녁 — 건물 검색: "이름이 없다"가 아니라 "이름이 있는데 못 찾는다"였다

건축물대장에는 이름 칸이 둘인데(`bld_nm` 건물명 · `dong_nm` 동명칭) 검색·화면이 **앞의 하나만** 보고 있었다.

| 검사 | 결과 | 판정 |
|---|---|---|
| 대조군 A — `bld_nm`에 있는 이름 10개 | 전부 1~2건 | 검색 자체는 정상 |
| 대조군 B — 없는 문자열 2개 | 전부 0건 | 아무거나 0건을 뱉지 않는다 |

⚠️ **RPC 256개도 노출돼 있으나 악용은 불가**(놀라지 말 것). PostGIS가 `public`에 있어 `/rpc/st_*` 등이 anon에게 호출 가능하다. DDL 계열을 컨테이너에서 직접 시험한 결과 **전부 막힌다** — `dropgeometrytable('public','parcel')` → `must be owner of table parcel`(표 생존 확인), `addgeometrycolumn`·`postgis_extensions_upgrade`·`enablelongtransactions`·직접 `CREATE TABLE` 모두 차단. 전부 `security_definer=false`라 호출자 권한으로 돌기 때문이다.
📌 다만 **우리 revoke는 표만 다뤘고 함수는 아니다.** Postgres는 새 함수의 EXECUTE를 기본으로 열어 주므로, 앞으로 `public`에 함수를 만들면 그 즉시 anon이 부를 수 있다 — 만들 때마다 노출 여부를 의식적으로 정할 것(`schema.sql` 주석에 규칙 기록).

⚠️ **못 막은 것 — PostGIS 시스템 표**: `spatial_ref_sys` 등 3개는 소유자가 `supabase_admin`이라 우리 `postgres` 롤로는 권한 회수가 안 된다(`set role supabase_admin`도 거부). 라이브 실측 결과 **anon에게 INSERT·DELETE 권한이 있다**(안전 시험 — 중복 키 409 / 0건 매칭 204).

**피해 범위를 컨테이너에서 정밀 측정했다**: anon이 좌표계 8,500행을 **전부 삭제할 수 있다.** 단 ① 우리 `parcel.geom` 값은 **그대로 살아남고 읽힌다**(저장된 도형이 SRID를 자기 안에 갖고 있어 이 표를 안 본다) ② 깨지는 건 **좌표 변환뿐**(`ST_Transform` → "Cannot find SRID (4326)"). ★ **현재 서비스 영향은 0이다** — 코드 전체에 `ST_Transform`·`ST_DWithin`·`::geography` 호출이 하나도 없고(grep 확인), 화면이 읽는 `v_floor_stack`에도 geom이 없다. 지도·반경 검색(§6.4)을 만들 때부터 문제가 된다. 원인은 PostGIS가 `extensions`가 아니라 `public` 스키마에 설치돼 REST에 노출되는 것(Supabase 공식 권장은 `extensions`).

🚧 **결정 (2026-08-08) — 공개 배포의 선행 게이트로 확정**: PostgREST 노출 스키마를 `public` → `api`로 바꿔 public 자체를 REST에서 없앤다. **오늘 실행하지 않는 이유**는 ① 앱이 배포 전이라 실제 노출 위험이 0이고 ② 필요한 두 전제(노출 목록에서 public 제거 가능 여부 / pass-through 뷰로 업서트 가능 여부)가 **공식 문서에 없어 미검증**이며 ③ 훼손돼도 우리 데이터가 아니라 PostGIS 표준 참조표라 복구가 되기 때문이다. 검증 안 된 큰 변경을 동작 중인 수집 파이프라인 위에 얹는 쪽이 더 큰 위험이다. **배포 착수 시 이 항목부터 처리한다** — 시험 항목·복구 절차는 마이그레이션 파일 §5.

### 추측 대신 **먼저 뽑아 봤다**

라이브(한국과학기술회관)를 A4 로 인쇄해 3장을 얻고, 거기서 나온 사실만으로 설계했다.
이 실측이 계획을 **두 군데나 뒤집었다**.

| 옛 메모 | 실측 |
|---|---|
| "카카오맵은 인쇄물 불가(약관·캡처하면 흰 화면) → 브이월드 정적지도로 교체" | ❌ **둘 다 틀렸다.** 카카오 공식 답변 = *"사용자 브라우저의 기본 기능을 통한 개인 목적의 PDF 출력은 데이터 별도 저장에 해당하지 않아 사용 가능합니다."* 금지 대상은 **캡처해 저장·가공·재배포**하는 쪽이다. 실측에서도 타일이 그대로 실렸다 — PDF 안 이미지 **21장**인데 우리 앱엔 그림 태그가 **0개**다 |
| (계획에 없던 것) | ⭐ **접힌 카드가 종이에서 통째로 빠졌다.** 『참고 매매 시세』가 제목만 남았다 |
| (계획에 없던 것) | ⭐ **막대가 전부 백지로 나왔다.** 브라우저가 배경색을 기본으로 인쇄하지 않아, 이 화면의 본론인 층별 스택이 사라졌다 |

브이월드로 갈아 끼우는 것은 오히려 손해였다 — 열쇠를 **브라우저에 새로 내놔야** 하고
(`.env` 에만 있다), 그 열쇠 등록 도메인이 `github.com/developer-duno/sangga` 라 안 맞고,
개발키가 **2027-02-09 만료**고, E2E 는 지도 열쇠를 일부러 비워 검증도 못 한다.

### 고친 것

- **`SectionCard` 가 접힌 본문을 그려 두고 감춘다**(`hidden`) — 인쇄 CSS 는 화면에 **없는
  것을 되살릴 수 없다.** 덤으로 사용자가 **Ctrl+P 를 직접 눌러도** 같은 종이가 나온다
  (인쇄 버튼을 눌렀을 때만 펼치는 방식은 그 길을 못 막는다).
- **`@media print` 블록** — 조종 장치 감춤 · `print-color-adjust: exact` · 페이지 나눔 ·
  마지막 장 여백 제거.
- **종이 전용 머리글**(`PrintHeader`) — 건물 이름·주소·뽑은 시각·원본 주소. 시각은
  `beforeprint` + `flushSync` 로 인쇄 직전에 다시 맞춘다(화면을 오래 열어 두고 뽑는 것이
  오히려 흔하다).
- **인쇄 버튼**(`PrintButton`) — 휴대폰에는 Ctrl+P 가 없다. 링크 복사와 한 줄에 둔다(`.takeout`).
- 층 상세는 **펼쳐 본 층만** 종이에 넣는다(👤 사장님 결정).

### 사장님 지적 — "위 아래 내용이 잘리지 않게 해야 하는 것 아니냐"

첫 인쇄물은 글자가 **종이 가장자리에 붙어** 있었다. 원인은 여백이 0 이었던 것이다 —
안 정해 두면 **어디서 뽑느냐에 따라 달라진다**(브라우저 인쇄 창은 사람이 고른 값, 프로그램
출력은 0). 0 이면 프린터의 인쇄 불가 영역(보통 3~5mm)에 걸려 **진짜로 잘린다.**
⇒ `@page { margin: 15mm 12mm }` 로 못 박았다(위아래를 좌우보다 넉넉히 — 장이 바뀌는 자리다).

이어서 "카드가 두 장에 걸쳐 동강 나는 것"도 손봤는데, **세 가지를 실제로 뽑아 견줬다**:

| 안 | 결과 |
|---|---|
| 카드 전체에 `break-inside: avoid` | ❌ **3장 → 4장**, 장마다 아래 3분의 1이 흰 종이(층 목록 카드가 한 장의 2/3를 먹어 남은 자리에 절대 안 들어간다) |
| 인쇄 글자 축소(12.5px) | ❌ **장수가 안 줄었다** — 장수를 정하는 건 글자 크기가 아니라 덩어리 크기였다. 되돌림 |
| **줄 단위 + 짧은 카드만** ✅ | **채택.** 3장 · 흰 자리 거의 없음 · 반으로 잘리는 곳 0 |

긴 목록 카드는 이어지게 두되(이어지는 줄에 "3층·2층·지1층"처럼 **이름이 붙어 있어** 다음
장에서도 무슨 표인지 안다), 줄 하나하나와 산문이 든 짧은 카드는 통째로 유지한다.
⚠️ **"추측 말고 뽑아 본다"가 여기서도 답을 뒤집었다** — 직관은 "카드를 통째로 유지하는 게
낫다"였는데, 실제로 뽑아 보니 종이 한 장이 통째로 낭비됐다.

### 파장 — 시험 8개가 "DOM 에 없다"를 보고 있었다

접힘을 "본문이 DOM 에 없다"로 확인하던 단언 8개(vitest 5 · vitest FloorStack 3)와 E2E 2곳이
깨졌다. **전부 "안 보인다"로 고쳤다** — 그게 사용자가 실제로 겪는 것이고, 앞의 것은 이제
거짓이다. 시험을 무르게 만든 것이 아니라 **보던 대상을 바로잡은 것**이다.

### 라이브러리를 안 쓴 이유 (오픈소스 먼저 찾기 규칙 이행)

후보 넷을 봤다. `react-to-pdf` 계열은 **화면을 사진으로 찍어** 지도 타일을 못 잡고 글자가
그림이 된다. `@react-pdf/renderer`·`pdfme` 는 종이용 화면을 통째로 새로 짜야 해 화면과 종이가
갈린다. `react-to-print` 는 CSS 로 되는 일에 스타일 어긋남 위험만 진다. ⇒ **브라우저 기본
인쇄 + `@media print`, 새 꾸러미 0개.**

### 검증

- 최종 인쇄물에서 **글자를 뽑아 대조** — 남아야 할 7가지(건물명·뽑음·서비스명·참고 매매
  시세·C등급·출처·면책) **전부 있음**, 빠져야 할 6가지(검색·선택 해제·지도 접기·의견
  보내기·인쇄 버튼·"지도를 누르면") **전부 없음**.
- 화면도 넓은 화면·휴대폰 두 폭에서 캡처해 확인(버튼 두 개가 나란히 / 세로로 쌓임).
