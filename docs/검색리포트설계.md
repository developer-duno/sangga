# 상가 공간분석 플랫폼 — 검색 진입점 & 리포트 설계

> 앞선 「데이터 전수조사」의 후속 문서. 데이터를 **어떤 기준으로 잘라서 소비자에게 보여줄 것인가**를 정의한다.

---

## 0. 핵심 전제 — 검색 의도가 두 갈래다

| 구분 | 조회형 | 탐색형 |
|---|---|---|
| 질문 | "이 자리 얼마야?" | "카페 할 자리 어디야?" |
| 시작점 | 지번 / 건물 / 상호 | 업종 + 지역 + 예산 |
| 사용자 | 건물주, 중개사, 계약 직전 창업자 | 창업 준비 초기, 투자자 |
| UI | 검색창 → 단일 물건 리포트 | 필터 → 지도 히트맵 → 후보 리스트 |
| 기존 서비스 | 밸류맵·디스코가 커버 | **비어 있음** |

아파트 서비스는 조회형만으로 충분했다. 단지를 이미 알고 검색하기 때문이다.
상가는 **"어디에 차릴지 모르는 상태"**에서 시작하는 사용자가 훨씬 많다.

> **결론: 탐색형을 메인 진입점으로 잡고, 조회형은 그 안에서 드릴다운되게 설계한다.**
> 두 플로우는 최종적으로 **같은 리포트**로 수렴한다.

## 1. 공간 계층 — 보고서 범위를 정하는 뼈대

모든 화면은 이 6단계 중 하나에 앵커된다.

| 레벨 | 단위 | 키 | 대표 질문 | 데이터 밀도 |
|---|---|---|---|---|
| **L0** | 호실 | PNU + 동 + 층 + 호 | 이 호실 얼마? | 낮음 (거래 희소) |
| **L1** | 층 | PNU + 동 + 층 | 이 건물 2층 시세? | 낮음 |
| **L2** | 건물 | PNU + 동 | 이 건물 어때? | 중간 |
| **L3** | 가로/블록 | 도로구간 or 반경 100m | 이 골목 어때? | 중간 |
| **L4** | 상권 | 반경 300~500m or 발달상권 경계 | 이 상권 어때? | **높음 (분석 주력)** |
| **L5** | 행정동/시군구 | 법정동코드 | 어느 동네가 좋아? | 높음 |

### 자동 확장 규칙 (중요)

L0에서 표본이 없으면 자동으로 위 레벨로 올라가되, **사용자에게 어느 레벨 데이터인지 반드시 표시**한다.

```
1) L0 (동일 호실 과거 거래)  → 있으면 사용, "실거래 기준" 표시
2) L1 (동일 건물 동일 층)    → 표본 1건 이상
3) L2 (동일 건물 타 층)      → 층별효용비율로 보정
4) L3 (반경 100m 동일 층)    → 표본 3건 이상
5) L4 (반경 500m 동일 층)    → 표본 5건 이상  ← 기본값
6) L5 (행정동 평균)          → 폴백, "참고용" 강조
```

**신뢰도 배지를 반드시 붙일 것.**
`실거래 3건 기반` / `유사물건 12건 추정` / `지역평균 참고` — 이 표시가 없으면 서비스 신뢰가 무너진다.

## 2. 검색창 설계 — 통합 인덱스

한 개의 검색창에서 4종류를 다 받는다.

| 입력 | 예시 | 매칭 소스 | 결과 |
|---|---|---|---|
| 지번 | 역삼동 123-4 | 법정동코드 + 지번 | L2 건물 리포트 |
| 도로명 | 테헤란로 123 | 도로명주소 API | L2 건물 리포트 |
| 건물명 | 강남파이낸스센터 | 건축물대장 건물명 | L2 건물 리포트 |
| **상호명** | 스타벅스 역삼점 | **상권정보 상호명** | L0 호실 리포트 |
| 상권명 | 강남역, 홍대 | 발달상권 경계 | L4 상권 리포트 |

### ★ 상호명 검색이 킬러 기능인 이유

소비자는 지번을 모른다. 하지만 **"그 가게 자리"는 안다.**

> "옛날에 ○○김밥 있던 자리 얼마야?"

이게 실제 사람들이 부동산을 인지하는 방식이다. 상권정보 데이터에 전국 상호명 + 층 + 호 + 좌표가 다 들어 있으므로 이 검색이 가능하다. **어떤 부동산 서비스도 이걸 안 한다.**

공실 이력이 쌓이면 더 강력해진다: "○○김밥 → 2025 Q3 폐업 → 현재 공실 4개월째"

## 3. 탐색형 진입 — 업종 기준 설계

### 3-1. 4단계 필터

```
① 뭘 하실 건가요?     → 업종 (247개 소분류 → 20개 대표 업종으로 압축)
② 어디서?             → 시군구 / 지하철역 / 현위치 반경
③ 예산은?             → 보증금 + 월세 상한
④ (선택) 조건         → 층, 면적, 주차, 역세권
```

⑤ **결과: 지도 히트맵 + 후보 상권 순위 리스트**

### 3-2. 업종별 입지 프로파일 — 추정하지 말고 실측하라

각 업종이 실제로 **어느 층에, 몇 평으로** 들어가 있는지는 상권정보 데이터로 집계하면 나온다. 감이 아니라 실측 분포다.

```
[예시 산출물 — 카페(소분류)]
층 분포:    1층 78% / 2층 15% / 지하 4% / 3층+ 3%
평균 밀도:  반경 500m당 12.3개
동반 업종:  의류(1.8배), 미용(1.5배), 서점(1.4배)
기피 업종:  주점(0.6배)
```

이 테이블을 업종 × 층 매트릭스로 미리 만들어두면:
- "이 자리(3층)에 카페? → 전국 카페의 3% 만 3층에 있습니다. 신중하세요"
- "이 자리(2층 40평)에 학원? → 전형적인 입지입니다"

이런 판정이 **데이터 근거를 갖고** 나온다.

### 3-3. 적합도 스코어

```
적합도 = 층적합(업종별 층분포)
       × 면적적합(업종별 면적분포)
       × 배후수요(세대수/직장인구/유동인구)
       × 경쟁여유(1 ÷ 동일업종 밀도)
       × 동반효과(보완업종 밀도)
       ÷ 임대부담(추정임대료 ÷ 업종 평균)
```

각 항목을 0~100으로 정규화해서 레이더 차트로 보여주면 소비자가 직관적으로 이해한다.

## 4. ★ 비교 상권 정의 — 거리가 아니라 유사도

**여기가 이 기획의 승부처다.**

아파트는 "인근 단지"가 직관적으로 성립한다. 상가는 아니다.
강남역 대로변 상가와 300m 떨어진 이면도로 상가는 **물리적으로 가깝지만 완전히 다른 시장**이다. 반경으로 비교하면 시세가 왜곡된다.

### 4-1. 상권 DNA 벡터

각 상권(L4)을 8차원 벡터로 표현한다. 전부 공개 데이터로 계산 가능하다.

| 차원 | 계산 방법 | 출처 |
|---|---|---|
| 업종 구성비 | 대분류 10개 비율 | 상권정보 |
| 점포 밀도 | 점포수 ÷ 면적 | 상권정보 |
| **프랜차이즈 비율** | 브랜드 상호 매칭 비율 | 상권정보 (상권 성숙도 지표) |
| 배후 수요 | 세대수 + 직장인구 | 통계청 |
| 도로 위계 | 도로접면 코드 분포 | NSDI 토지특성 |
| 역세권도 | 최근접 역 거리 | 지하철 좌표 |
| 지가 수준 | 개별공시지가 중앙값 | 국토부 |
| 건물 노후도 | 사용승인일 중앙값 | 건축물대장 |

### 4-2. 유사 상권 매칭

코사인 유사도로 상위 5개 상권을 뽑는다.

```
"내가 보는 이 자리와 비슷한 상권"
→ 유사도 0.91  A상권  ㎡당 임대료 4.2만원
→ 유사도 0.88  B상권  ㎡당 임대료 3.8만원
→ 유사도 0.85  C상권  ㎡당 임대료 5.1만원
────────────────────────────────
현재 자리: 5.4만원  → 유사 상권 대비 +28% 비쌈 ⚠
```

**"인근 대비"가 아니라 "유사 상권 대비"** 로 판정하는 것 —
이게 밸류맵·디스코가 안 하는 부분이고, 소비자가 진짜 알고 싶어 하는 답이다.

### 4-3. 부수 효과: 상권 발견

유사도 매칭은 반대로도 쓸 수 있다.

> "강남역 상권과 성격은 비슷한데 임대료는 40% 싼 곳" → 5곳 추천

이건 창업자에게 강력한 유인이고, 서비스 바이럴 포인트가 된다.

## 5. 리포트 구성 (단일 표준 화면)

조회형·탐색형 어느 쪽으로 들어와도 최종 도착지는 동일하다.

| 순서 | 블록 | 내용 |
|---|---|---|
| 1 | **헤더** | 주소, 건물명, 층/호, 전용면적, 현재 상태(영업중 ○○ / 공실 N개월) |
| 2 | **추정 시세** | 매매 밴드 + 임대 밴드 + **신뢰도 배지** |
| 3 | **인근 실거래** | 동일 층 우선, 지도 + 리스트, 최근 24개월 |
| 4 | **유사 상권 비교** | 5개 상권 대비 싸다/비싸다 판정 |
| 5 | **업종 적합도** | 선택 업종 레이더 차트 + 추천 업종 TOP3 |
| 6 | **경쟁·동반 지도** | 반경 500m 동일업종(빨강) / 보완업종(파랑) |
| 7 | **공실 이력** | 이 호실의 업종 변천사 (데이터 누적 후) |
| 8 | **건물 정보** | 준공년도, 연면적, 용적률, 주차, 용도지역, 도로접면 |
| 9 | **주의사항** | 참고 시세임을 명시 + 표본수 공개 |

### 공유용 PDF

7번 공실 이력과 4번 유사 상권 비교는 **중개 실무에서 그대로 쓸 수 있는 자료**다.
"이 자리는 3년간 3번 바뀌었습니다" vs "5년째 같은 업종입니다" — 이 한 줄이 계약을 좌우한다.

## 6. 기술 함정 — 미리 알아둘 것

### 6-1. PNU 조립 문제 ★

실거래가 API에는 **PNU가 없다.** 법정동코드와 번지만 온다. 직접 조립해야 한다.

```
PNU 19자리 = 법정동코드(10) + 대지구분(1) + 본번(4) + 부번(4)

예) 법정동코드 1168010100
    대지구분   1 (일반) / 2 (산)
    본번       0123  ← 4자리 zero-fill
    부번       0004  ← 4자리 zero-fill
→ PNU: 1168010100100230004
```

**이 조립 로직이 전체 파이프라인의 병목이자 핵심**이다. 여기서 틀리면 모든 조인이 깨진다.

### 6-2. 주소 표기 불일치

| 소스 | 주소 형태 |
|---|---|
| 실거래가 | 법정동명 + 번지 (통건물은 일부만) |
| 상권정보 | 지번주소 + 도로명주소 + PNU |
| 건축물대장 | 대지위치 + 시군구코드/법정동코드/번/지 |

→ **상권정보에 PNU가 있으므로 이걸 마스터 테이블로 삼고**, 나머지를 붙이는 게 가장 빠르다.

### 6-3. 층 표기 정규화

`1`, `1층`, `B1`, `지하1층`, `-1`, `101호(1층)` … 소스마다 다르다.
정수형 규칙을 먼저 정하라: **지상 n층 = n, 지하 n층 = -n, 옥탑 = 99**

### 6-4. 검색 성능

전국 상호명은 수백만 건이다. DB `LIKE` 검색으로는 못 버틴다.
초기엔 시군구 단위로 범위를 좁히고, 규모가 커지면 검색 엔진(Meilisearch 등) 도입.

### S3의 핵심 UI — 층별 스택 뷰

건물을 **세로 단면**으로 그린다. 아파트 서비스에 없는 화면이고, 상가의 본질을 가장 잘 보여준다.

```
┌──────────────────────┐
│ 4F  ○○학원      45평 │  추정 월 180만
├──────────────────────┤
│ 3F  ○○의원      52평 │  추정 월 210만
├──────────────────────┤
│ 2F  [공실 6개월] 48평 │  추정 월 240만  ← 클릭
├──────────────────────┤
│ 1F  ○○카페      22평 │  추정 월 320만
├──────────────────────┤
│ B1  ○○주점      60평 │  추정 월 150만
└──────────────────────┘
```

한 화면에 층별효용비율, 업종 구성, 공실이 다 들어온다.

## 8. 다음 결정 사항

1. **탐색형 vs 조회형 중 어느 쪽을 먼저 만들 것인가** (권장: 조회형 S3부터 — 데이터 검증이 되고 중개 실무에 즉시 쓰임)
2. **업종 대표 20개 선정** (247개 전부는 초기에 불가)
3. **상권 경계 정의** (발달상권 데이터 사용 vs 자체 클러스터링)
4. **파일럿 지역** (익숙한 지역 1개 시군구 권장 — 결과 검증이 가능해야 함)
