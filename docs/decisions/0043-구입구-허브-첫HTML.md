## 결정

1. 만들기: 「지금 만든다」 — 건물마다 들어오는 링크가 0→1 이 되어 구글이 '중요한 쪽'으로 볼 근거가 생김 · 0042 문서도 이게 다음 수라고 적어 둠.
2. 주소: 「지금 구 입구 주소」 — /?sgg=11680 — 이미 빵부스러기가 가리키는 주소라 그대로 허브가 됨. 사람에겐 지금처럼 구 화면이 열리고, 첫 HTML 에만 건물 목록 링크가 들어감(건물 쪽과 같은 방식).
3. 제목: 「○○구 상가 건물 층별 보기」 — 예: 「강남구 상가 건물 층별 보기 — 상가 층별 스택뷰」.
4. 차례: 「가나다순」.
5. 한 줄: 「이름 + 도로명」 — 예: 「코엑스 · 영동대로 513」.
6. 같은 이름 구: 「모든 구에 시 이름 붙임」 — 「서울 강남구 상가 건물 층별 보기」·「대전 중구 …」.
(메인 판단 — 알리고 진행: 목록은 빌드 때 굽는 파일(새 DB 함수 0 · 요청 때 DB 0) · 설명 글 = 소개문 그대로 · 허브 주소 사이트맵 따로.)

## 설계 (지시서 `brief-0043-impl.md` ③ 표 H1~H13 이 항목 정본)

- **주소 판정**(`src/lib/buildingRoute.ts` `hubRewriteTarget` · 레포 루트 `middleware.ts`): 건물 갈래(`buildingRewriteTarget`)가 먼저, 그다음 허브 갈래. `/` 이고 **`bld` 인자가 아예 없고** `sgg` 가 5자리 숫자일 때만 `/api/hub?sgg=<sgg>`(`sgg` 하나만 다시 조립 — 낯선 인자로 캐시 칸을 늘리지 못하게). `bld` 가 있으면 꼴이 틀려도 허브가 아니다(건물 갈래 규칙 그대로).
- **굽기**(`scripts/build_sitemap.py`): 사이트맵과 **같은 대상 질의 한 번**(`TARGET_WHERE` 그대로 · 찬 캐시 약 10분)에 허브 재료를 함께 읽는다 — 뷰 `v_floor_stack` 과 같은 칸(`building.display_nm` · `parcel.road_addr` · 같은 땅 동 수) + 같은 땅 2동 이상이면 `list_parcel_buildings(pnu)` 의 (bld_id, bld_nm, dong_nm)을 함수 차례 그대로(서버 조각이 부르던 그 함수 · 새 함수 정의 0) + `mv_open_sigungu` 의 시·도 코드·구 이름. 열린 구이고 대상이 1동 이상인 구만 `public/hub/<sgg>.json`(키 정렬 · LF · 결정적) · 옛 허브 파일은 지우고 새로. 열린 구 밖 대상은 허브에서만 빠지고 굽기 출력에 「[주의]」 한 줄. `public/sitemap-hubs.xml`(lastmod 없음)을 색인의 home 다음에.
- **파이썬에는 재료만** — 이름·동 구분 글은 TS 가 만든다(`src/lib/hubHead.ts` → `buildingHead.ts` 의 `dongSuffix` · 시·도 짧은 이름표는 `src/lib/regions.ts` 의 `SIDOS` 하나).
- **서버 조각**(`api/hub.ts` → `src/lib/hubHandler.ts`): 같은 배포의 `/index.html` 과 `/hub/<sgg>.json` 을 함께(각 3초 · 허용 호스트 규칙 = 건물 쪽 `homeSource` · cookie 는 허용 호스트일 때 두 요청 모두에 — 아래 「미리보기 배포」). 응답 — 첫 화면 못 받음 307 `/index.html?sgg=<sgg>`(no-store) · 허브 파일 404 첫 화면 200 하루(모르는 구 = 지금과 같음) · 그 밖 실패 503 + Retry-After 120 + 첫 화면(no-store) · 모양 틀림·치환 실패 첫 화면 200 no-store + console.error · 정상 허브 HTML 200 하루 + 일주일 SWR.
- **바꾸는 자리**(`renderHubHtml` · 태그마다 정확히 1번 · 함수 치환): 제목·og:title·twitter:title = `<시> <구> 상가 건물 층별 보기 — 상가 층별 스택뷰` · h1 `h1.seo-title` = `<시> <구> 상가 건물 층별 보기` · 소개문 = description·og·twitter 설명 = `<시> <구>에서 층별 화면을 볼 수 있는 상가 건물 N곳입니다.`(N = 그 허브에 실은 건물 수) · canonical·og:url = `https://sangga-one.vercel.app/?sgg=<sgg>` · 본 JSON-LD = 첫 화면 것에서 이름·설명·주소(url)만 허브 값(나머지 칸·종류 `WebApplication` 그대로 — 새 사실 0) · 빵부스러기(BreadcrumbList) = 「상가 층별 스택뷰」(첫 화면) → `<시> <구>` · `nav.seo-links` = 건물 링크 전부(`<이름> · <짧은 도로명>` · 주소는 사이트맵 `building_loc` 과 같은 꼴 `/?sgg=<pnu 앞 5자리>&bld=<id>`) + 「첫 화면」 `/`.
- **이름 = 그 건물 쪽 첫 HTML 의 h1 글자**(H10) — 같은 함수(`dongSuffix`)·같은 재료(동 목록 · 동 수 = 뷰 `bld_cnt_in_pnu` 와 같은 셈)·같은 조건(같은 땅 2동 이상이고 이름이 있을 때만 동 구분). vitest 짝 시험이 같은 고정물로 `renderBuildingHtml` 의 h1 과 대조한다.
- **차례**: 링크 글자의 글자 부호 차례(한글 음절은 부호가 가나다 차례다 · 같으면 bld_id) — 실행 환경의 로캘 자료에 기대지 않는다.
- **JSON-LD 종류**: `WebApplication` 그대로 둔다(지시 「이름·설명·주소만」). ⓘ 허브는 목록 페이지라 `CollectionPage`(+ `isPartOf` WebApplication — 건물 쪽 `WebPage` 꼴)가 더 맞을 수 있다 — 근거: schema.org 의 `CollectionPage` 정의가 「목록 페이지」 · 건물 쪽은 이미 `WebPage` 로 바꿔 쓴다. 바꿀지는 별도 판단(이번엔 안 바꿈).
- **cookie(메인 판단 2026-10-18)**: 허용 호스트(정식 · `VERCEL_URL` · `VERCEL_BRANCH_URL`)일 때 들어온 cookie 를 같은 배포의 두 요청(`/index.html` · `/hub/<sgg>.json`) 모두에 싣는다 — 둘 다 같은 출처 정적 파일이라 위험이 같고, 배포 보호가 걸린 미리보기 배포에서 허브를 실제로 확인하려면 필요하다. 남의 호스트면 둘 다 정식 주소 고정 + cookie 0(건물 쪽 규칙 그대로). Supabase 호출은 없다.
- 시험: `src/lib/buildingRoute.test.ts`(허브 갈래 + 건물 갈래) · `src/lib/hubHead.test.ts`(치환 정확히 1번 · 0/2개 throw 양성 대조 · 이스케이프 · 제목·h1·소개·canonical·빵부스러기 글자 · 가나다 · H10 짝 · 금지어·판단 낱말·코드 속 지역 이름 가드 + 양성 대조 · 커밋된 허브 파일을 실제 `index.html` 로 구워 사이트맵 주소 집합과 대조) · `src/lib/hubHandler.test.ts`(응답 갈래 전부 · 허용 호스트 · cookie) · `tests/test_build_sitemap.py`(허브 굽기 · 결정성 · 옛 파일 지우기 · 허브 건물 = 사이트맵 건물 · 대상 SQL 을 로컬 PostgreSQL 에서 실제 `list_parcel_buildings` 정의로 실행).

## 되돌리기

- 허브만 끄기 = `middleware.ts` 의 허브 갈래(`?? hubRewriteTarget(request.url)`) 삭제 → 구 입구는 즉시 옛 동작(첫 화면 그대로). `api/hub.ts`·`public/hub/*.json` 은 남아도 안 불린다.
- 사이트맵에서도 빼기 = `build_sitemap.py` 를 되돌려 다시 굽는다(`sitemap-hubs.xml` 이 색인에서 빠진다).
