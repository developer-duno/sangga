## 무엇이 문제였나

세 역할의 공통 여정은 **들어옴 → 찾음 → 한 장 요약 → 가지고 나감**이다. 0019 로 "주소로
들고 다니기"가 채워졌지만 **종이는 여전히 비어 있었다** — 화면 코드에 인쇄 관련 규칙이
`@media print` 기준 **0건**이었다.

문제를 추측으로 적지 않고 **라이브에서 실제로 A4 로 뽑아 봤다**(2026-08-25, 한국과학기술회관).
인쇄 규칙이 한 줄도 없는 상태의 결과 3장에서 드러난 것:

| | 무엇이 | 왜 문제인가 |
|---|---|---|
| 1 | 첫 장 위 절반이 **조종 장치** — 제목·설명·지역 안내·구 칩·검색창·선택 해제·지도 접기·링크 복사 | 종이에서 누를 수 없는 것들이 본론 자리를 먹는다 |
| 2 | **『참고 매매 시세』가 제목만 나오고 값이 통째로 빠짐** | 접힌 카드는 본문이 *안 보이는* 게 아니라 **아예 안 만들어졌다** |
| 3 | **층별 막대·업종 막대가 전부 사라짐** | 브라우저는 잉크를 아끼려고 배경색을 기본으로 인쇄하지 않는다. 이 화면 이름이 "층별 스택"인데 그 스택이 백지가 된다 |
| 4 | ▼▲ 화살표·업종 고르는 칸·"의견 보내기" 버튼이 그대로 인쇄됨 | 같은 이유 |
| 5 | **뽑은 시각도, 원본 주소도 없음** | 종이만 봐서는 언제 것이고 어디서 다시 보는지 알 수 없다 |
| 6 | 페이지가 아무 데서나 잘림 · 마지막 장의 3/4이 빈 종이 | |

## 결정 1 — **브라우저 기본 인쇄 + 인쇄 전용 CSS.** 라이브러리를 안 쓴다

오픈소스를 먼저 찾는 것이 우리 규칙이라 후보 넷을 봤다.

| 후보 | 판단 |
|---|---|
| `react-to-pdf` 계열 | ❌ **화면을 사진으로 찍는 방식**(html2canvas). 지도 타일은 다른 집 그림이라 캔버스가 더럽혀져 **못 잡고**, 글자가 그림이 돼 복사·검색이 안 된다 |
| `@react-pdf/renderer` · `pdfme` | ❌ 종이용 화면을 통째로 새로 짜야 한다. 화면을 고칠 때마다 종이도 따로 고쳐야 하고, 그러다 둘이 갈린다 |
| `react-to-print` | ❌ 일부만 인쇄하려고 화면을 복사해 넣는 방식. CSS 로 되는 일에 스타일이 어긋날 위험만 진다 |
| **브라우저 기본 인쇄 + `@media print`** ✅ | **채택.** 새 꾸러미 **0개**. 글자가 글자로 남아 복사·검색이 되고, PDF 저장도 인쇄 창에서 그대로 된다 |

## 결정 2 — 지도는 **카카오 그대로 인쇄한다** (옛 메모가 틀렸다)

⛔ 예전 메모의 *"카카오맵은 인쇄물에 못 쓴다(약관·캡처하면 흰 화면) → 브이월드 정적지도로
갈아 끼워라"* 는 **사실이 아니었다.** 둘 다 확인했다.

- **약관** — 똑같은 질문(브라우저로 PDF 인쇄할 때 지도가 함께 나오는 것)에 대한 카카오
  공식 답변이 있다: *"사용자 브라우저의 기본 기능을 통한 개인 목적의 PDF 출력은 데이터
  별도 저장에 해당하지 않아 사용 가능합니다."* 금지되는 것은 지도를 **캡처해 저장·가공·
  재배포**하는 쪽이다. 옛 메모의 "캡처하면 흰 화면"은 그 사진 찍는 방식 얘기였는데, 인쇄
  얘기로 잘못 옮겨 적혔다.
- **실측** — 위 A4 3장에 지도가 타일·마커·범례·출처까지 그대로 실렸다. PDF 안 이미지가
  **21장**인데 우리 앱에는 그림 태그가 **하나도 없다** — 21장 전부 지도 타일이다.

브이월드로 갈아 끼우는 것은 **오히려 손해**다:

| | 브이월드로 바꾸면 |
|---|---|
| 열쇠 | `VWORLD_KEY` 는 지금 `.env` 에만 있다 — **브라우저에 새로 내놔야 한다**(새 노출면) |
| 도메인 | 그 열쇠에 등록된 주소가 `https://github.com/developer-duno/sangga` 라 우리 사이트와 안 맞는다(`INCORRECT_KEY`) |
| 만료 | 개발키 만료 **2027-02-09** — 만료되는 날 종이의 지도만 조용히 깨진다 |
| 검증 | E2E 는 지도 열쇠를 **일부러 비운다** — 새로 넣은 지도를 시험이 볼 수 없다 |

⛔ 다만 허용된 것은 **사용자가 자기 브라우저로 뽑는 것**뿐이다. 지도를 그림 파일로 만들어
서버에 저장하거나 재배포하는 코드는 쓰지 않는다.

⛔ **접어 둔 지도는 종이에도 안 나온다.** 접으면 지도를 아예 그리지 않기 때문이고, 사용자가
일부러 접은 것이므로 그 뜻을 존중한다. (카드의 접힘과는 다른 경우다 — 아래 결정 3.)

## 결정 3 — **접힌 카드의 본문은 그려 두고 감춘다** (지우지 않는다)

문제 2가 이 결정의 이유다. 예전에는 접히면 본문을 **DOM 에서 아예 뺐다**(`{open && ...}`).
인쇄 규칙(CSS)은 보이는 것을 바꿀 뿐 **화면에 없는 것을 되살릴 수는 없다** — 그래서 접힌
카드가 종이에서 통째로 빠졌다.

⇒ `SectionCard` 가 본문을 항상 그리고 `hidden` 으로 감춘다. 화면 동작은 똑같다(`hidden` 은
눈에서도, 읽어 주는 기기에서도 감춘다). 인쇄에서는 한 줄로 되살아난다.

**왜 "인쇄 버튼을 누르면 다 펼치기"가 아닌가** — 사용자는 언제든 Ctrl+P·브라우저 메뉴·
공유 시트로 인쇄한다. 버튼을 거치는 방식은 그 길들을 못 막아, 다른 길로 들어온 사람에게
**말없이 반쪽짜리 종이**를 준다. 접힘 펼치기는 버튼이 아니라 **CSS** 가 해야 어느 길로
와도 같은 종이가 나온다.

⚠️ **파장**: "접히면 DOM 에 없다"를 보던 시험 8개가 깨졌다. 전부 **"안 보인다"**를 보도록
고쳤다 — 그게 사용자가 실제로 겪는 것이고, 앞의 것은 이제 거짓이다.

## 결정 4 — 층 상세는 **펼쳐 본 층만** 종이에 넣는다 (사장님 결정)

| 후보 | 판단 |
|---|---|
| **펼쳐 본 층만** ✅ | **채택.** 지금 화면 동작 그대로다. 종이는 보통 2~3장이고 *"내가 화면에서 본 것을 그대로 남긴다"*라 결과가 예측된다 |
| 모든 층을 다 | ❌ 건물에 따라 5~10장. 현장 대조에는 좋지만 대부분의 쓰임에 너무 길다 |
| 아예 안 넣기 | ❌ 펼쳐서 본 것이 종이에 없으면 이상하게 느껴진다 |

## 종이에서 빼는 것 / 남기는 것

**빼는 것** — 지역 고르개(`.region`) · 검색(`.search`) · 가지고 나가기 줄(`.takeout`) ·
의견함(`.fb`) · 지도 접기 버튼 · "지도를 누르면…" 안내 · 업종 고르는 칸 · 접기 화살표 ·
안내 팝업 · 서비스 제목과 설명(`.app__head` — 머리글이 대신한다).

**남기는 것** — 지도 · 속한 상권 · 층 목록 · 둘레의 업종 분포 · 실거래 기록 · 참고 매매
시세 · **등급 배지 · 근거 · 표본 수 · 출처 · 면책**.

⛔ **근거·표본·출처·면책은 종이에서 절대 빼지 않는다.** 절대 규칙 3(값과 근거는 한 몸)과
공공누리 1유형(출처표시) 의무는 매체가 바뀐다고 사라지지 않는다. 오히려 종이는 화면보다
멀리 돌아다니므로 더 중요하다.

## 종이에만 나오는 머리글

`.printmeta` — 건물 이름 · 주소 · `상가 층별 스택뷰 · YYYY-MM-DD HH:MM 뽑음 · 원본 주소`.

- **시각은 인쇄가 시작되기 직전에 다시 맞춘다**(`beforeprint` + `flushSync`). 화면을 열어
  두고 한참 뒤에 뽑는 것이 오히려 흔하다. 못 맞춰도 화면을 연 시각이 적힐 뿐 종이가 깨지지는
  않는다.
- **시간대는 보는 사람의 것**을 쓴다 — 자료의 기준 시점이 아니라 "이 종이를 뽑은 시각"이라
  뽑은 사람의 시계가 맞다. (자료 기준 시점은 각 섹션이 자기 출처 줄에 따로 적는다.)
- 원본 주소는 **링크 복사 버튼과 같은 값**을 쓴다(`App.tsx` 의 `shareUrl` 하나). 두 곳에서
  따로 만들면 언젠가 한쪽만 고쳐져 갈린다.
- QR 이 아니라 **글자 그대로** 적는다 — 꾸러미가 하나 더 붙는데, 물음표 방식이라 주소가
  손으로 옮겨 적을 만한 길이다(0019).

## 결정 5 — 여백은 **우리가 못 박고**, 나눔은 **줄 단위로만** 막는다

사장님 지적 *"프린트로 뽑을 때 위 아래 내용이 잘리지 않게 해야 하는 것 아니냐"* 에서 나온
결정이다. 실제로 첫 인쇄물은 글자가 종이 가장자리에 붙어 있었다.

### 여백 (`@page { margin: 15mm 12mm }`)

안 정해 두면 여백이 **어디서 뽑느냐에 따라 달라진다** — 브라우저 인쇄 창은 사람이 고른 값을
쓰고, 프로그램으로 뽑으면(미리보기·자동 출력) **0** 이 기본이다. 0 이면 글자가 가장자리에
붙어 잘린 것처럼 보이고, 프린터의 인쇄 불가 영역(보통 3~5mm)에 걸리면 **진짜로 잘린다.**
위아래를 좌우보다 넉넉히 둔다 — 장이 바뀌는 자리가 위아래라 그쪽이 체감을 좌우한다.

### 나눔 — 카드에는 안 걸고, 줄과 짧은 카드에만 건다

세 가지를 **실제로 뽑아 견줬다**(같은 건물, A4):

| 안 | 결과 |
|---|---|
| 여백만 | 3장. 다만 카드가 장을 넘어 이어진다 |
| **카드 전체에 `break-inside: avoid`** | ❌ **3장 → 4장**, 장마다 아래 3분의 1이 흰 종이. 층 목록 카드 하나가 한 장의 3분의 2를 먹어 남은 자리에 절대 안 들어가기 때문이다 |
| 인쇄 글자 축소(12.5px) | ❌ **장수가 안 줄었다.** 장수를 정하는 것은 글자 크기가 아니라 덩어리 크기였다. 읽기만 나빠져 되돌림 |
| **줄 단위 + 짧은 카드만** ✅ | **채택.** 3장 · 흰 자리 거의 없음 · 반으로 잘리는 곳 0 |

채택안의 규칙:

- **긴 목록 카드는 이어지게 둔다** — 이어지는 줄에 "3층 · 2층 · 지1층"처럼 **이름이 붙어
  있어**, 다음 장에서 제목이 없어도 무슨 표인지 바로 안다.
- **줄 하나하나는 안 잘리게 한다**(`.floor` · 밴드 줄 · 업종 줄 · 실거래 줄). 이게 잘림을
  막는 최후의 방어선이다.
- **산문이 든 짧은 카드는 통째로 유지한다**(속한 상권 · 등급 설명 · 면책 · 건물 머리 · 지도).
  문장이 두 장에 걸리면 읽는 흐름이 끊기고, 짧아서 밀어도 흰 자리가 거의 안 생긴다.
- **제목만 장 끝에 혼자 남지 않게** 한다(`break-after: avoid`).

⚠️ `break-inside: avoid` 는 "무조건"이 아니라 **"가능하면"** 이다 — 한 장보다 큰 덩어리는
그때 쪼갠다. 그래서 층이 수십 개인 건물에서도 종이가 멈추지 않는다.

## 검증

- 화면 시험(vitest) — `printStamp` 5개 · `PrintButton` 3개 · `PrintHeader` 6개 신설,
  접힘 관련 8개를 "안 보인다"로 교정.
- **E2E 신설 R·S** — jsdom 은 스타일시트를 안 읽어 "종이에서 무엇이 보이나"를 원리적으로
  못 본다. 인쇄 매체를 흉내 낼 수 있는 곳은 E2E 뿐이다(`page.emulateMedia({media:'print'})`).
  - R: 조종 장치가 빠지고 머리글이 붙는가 · 본론과 근거·출처·면책이 남는가
  - S: **접어 둔 카드가 종이에는 나오는가** · **막대 색이 지워지지 않는가**(`print-color-adjust: exact`)
    · **줄이 반으로 안 잘리는가**(`.floor` 의 `break-inside: avoid`) · **짧은 카드는 통째로
    유지되는가**(`.card--district`)
- 최종 인쇄물에서 **글자를 뽑아 대조** — 남아야 할 7가지(건물명·뽑음·서비스명·참고 매매
  시세·C등급·출처·면책) 전부 있음, 빠져야 할 6가지(검색·선택 해제·지도 접기·의견 보내기·
  인쇄 버튼·"지도를 누르면") 전부 없음.
- 화면도 넓은 화면·휴대폰 두 폭에서 캡처해 확인(버튼 두 개가 나란히 / 세로로 쌓임).
