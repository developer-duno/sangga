# 0037 — 건물마다 검색에 따로 나오게 하기(건물별 첫 HTML · 사이트맵)

- 날짜: 2026-10-09 (조사·설계안 · 👤 결정 18:0x) · 상태: **확정 — 👤 결정 ① A 서버 조각 · ② 비주거 층 있는 13,324동(19:1x 재결정 — 처음 36,472) · ③ 제목 `이름 — 구 도로명 | 상가 층별 스택뷰` · ④ 주소 `?sgg=&bld=` 그대로**(넷 다 추천안)
- 배경: 2026-10-09 (6) SEO 기본 세팅 뒤 맹점 검사관 🟠 1 — "건물 주소(`?sgg=&bld=`)도 canonical·og:url 이 첫 화면이라 구글이 건물 페이지를 전부 첫 화면 하나로 합친다". 사람들은 "OO빌딩 상가"처럼 **건물 이름**으로 검색하므로, 지금 구조로는 우리 건물 화면이 검색에 안 나온다.

**공식 문서(2026-10-09 확인)**
- 구글 JS SEO: "canonical 은 HTML 로 두는 것이 최선 · JS 로 바꾸는 것은 비권장(가능은 함)" · 렌더링 대기열은 "몇 초에서 더 오래". **서버 렌더링·미리 굽기는 '여전히 좋은 생각'**.
- 구글 동적 렌더링(봇에게만 다른 HTML): "**해결책이 아니라 우회책**" · 내용이 비슷하면 클로킹은 아님 → **모두에게 같은 HTML** 을 주면 이 걱정이 없다.
- 구글 사이트맵: 파일당 50,000 URL · 50MB · 색인 파일(sitemap index)로 여러 개 묶기 가능 · `lastmod` 는 정확할 때만.
- Vercel 함수: 프레임워크가 Vite 든 "other" 든 **`api/<이름>.ts` 파일 하나**가 서버 함수가 된다(`export default { fetch(request) {…} }`). `vercel.json` `rewrites` 는 **`has: [{type:"query", key:"bld"}]`** 로 "주소에 bld 가 있을 때만" 함수로 보낼 수 있다(헤더 조건도 됨).
- Vercel Hobby(무료) 한도: 함수 호출 월 100만 · CPU 4시간 · 전송 100GB · **비상업 개인용만**(광고·결제가 생기면 Pro $20/월). 지금 사이트는 무료·광고 0 이라 해당 없음.

## 3. A 안 상세(결정 ②~④가 정해지면 확정)

**흐름**: `/?sgg=11680&bld=…` 요청 → `vercel.json` rewrite(`has` query `bld`) → `api/building.ts` → ① 같은 배포의 `/index.html` 을 가져온다(정적 · 빌드 산출물 그대로) ② Supabase REST `api.v_floor_stack?bld_id=eq.<id>`(anon 공개키 · 화면이 쓰는 것과 같은 뷰) ③ `<title>`·`description`·`canonical`·`og:*`·`twitter:*`·JSON-LD·`<p class="seo-intro">` 를 그 건물 값으로 치환 ④ `Cache-Control: s-maxage=86400, stale-while-revalidate` 로 CDN 에 하루 보관 ⑤ 건물이 없으면 **404 상태 + 첫 화면 HTML**(앱이 "못 찾음"을 띄운다 · 구글이 쓰레기 주소를 색인하지 않게).
- 바꾸지 않는 것: 공개 주소 꼴(`?sgg=&bld=` 그대로 — 프롬프트 §1-2 "기존 URL 유지") · React 앱 · DB 함수 · 첫 화면 HTML.
- 건물 제목 꼴(결정 ③): `<건물 이름> — <구> <도로명> | 상가 층별 스택뷰` 처럼 **구·도로명을 붙여** 같은 이름을 구분.
- 소개문(첫 HTML 본문): "<이름>(<도로명>)은 지상 n층·지하 m층, 층별 호실 k개 … 1층 …㎡" — **v_floor_stack 에 있는 사실만**(얇은 페이지 금지 · 지어낸 숫자 0 · 금지어 0).
- 사이트맵: `scripts/build_sitemap.py` 가 DB 에서 대상 건물을 읽어 `public/sitemap-buildings-1.xml`(≤50,000) … 와 색인 `sitemap.xml`(첫 화면 + 건물 파일들)을 굽는다 — 건축물대장 재적재 뒤 한 번(post_load 안내에 한 줄). 36k 기준 파일 2개 · 약 4MB(레포에 커밋 · 함수 호출 0).
- 지킴: `tests/test_sitemap_build.py`(50,000 상한 · 정식 주소 · 대상 조건) · `api/building.test.ts`(vitest — 치환 각 1회 · 금지어 0 · 없는 건물 404 · fetch 목업) · 라이브 = 카카오 봇 UA·일반 UA 로 받은 HTML 이 같은지 + 서치콘솔 URL 검사.
- 비용: 0원(Hobby 안) · 함수 1개 · Supabase 호출은 CDN 캐시로 건물당 하루 1회.
- 순서: PR① 함수 + rewrite + 시험(배포 뒤 건물 하나로 라이브 확인 · 서치콘솔 URL 검사 '색인 가능') → PR② 사이트맵 스크립트 + 파일 + 서치콘솔 제출 + IndexNow 알림 → 몇 주 뒤 서치콘솔 '페이지' 보고서로 색인 수 확인.
- 되돌리기: `vercel.json` 의 rewrite 한 줄을 지우면 즉시 옛 동작(함수 파일은 남아도 안 불린다).
