2026-08-27 LH 공고문 API 활용신청이 승인돼 재료가 생겼다. 실측으로 확정한 경계:

## 결정 1 — 감시는 자동, 적재는 로컬 수집기만 (절충)

사장님이 "프로젝트 목적·사용자 편의·데이터 관리를 근거로 냉정하게" 위임한 결정.

| 후보 | 판단 |
|---|---|
| 완전 수동(주 1회 사람이 수집) | ❌ 사람이 잊는 순간 낡는다 — 이 레포가 감시 그물을 계속 늘려 온 이유가 바로 그것 |
| 완전 자동(Actions 가 DB 적재까지) | ❌ **DB 쓰기 열쇠를 GitHub 에 내보내야 한다** — 데이터 관리상 최악 |
| **절충** ✅ | Actions 는 **확인만**(주 1회, 새 상가 공고 있으면 이슈 — 기존 그물 4종과 동형, 그물 5호로 편입해 서로 감시). 적재는 지금까지처럼 **로컬 수집기**(관문·upsert). GitHub 에 나가는 건 포털 API 열쇠(`MOLIT_KEY` Secrets) 하나뿐 — 노출 피해가 쿼터 도용 수준이고 재발급으로 끝난다 |

기준선 방식은 분기 스냅샷 감시의 선례(`LATEST_KNOWN_QUARTER`) 그대로:
`check_lh_notices.py` 의 `LATEST_KNOWN_NOTICE_DATE` 를 **적재한 사람이** 그 판의 최근
공고일로 올린다(수집기가 마지막 줄에 값을 알려 준다).

## 결정 2 — 입구 접힘 카드 (구를 골랐고 건물은 아직일 때만)

- 지역이 시도 단위 정보라 건물 화면(층별 스택)보다 **입구 문맥**이 맞다. 건물을 고르면
  카드가 사라진다(분석 화면을 어지럽히지 않기 — 선택 해제하면 다시 보임).
- 요약 한 줄 = "N건 · M월 D일 수집 기준" — **낡음을 감추지 않는 정직 표기**.
- 줄마다 유형 배지(분양 입찰/임대 추첨/임대 입찰/공모·심사)·공고명·상태·마감일·
  **[LH에서 보기]** 링크. 가격·추정 정보 0(절대 규칙 2·3과 충돌 없음).
- ⛔ 카드 틀은 `ENTRY_SECTION_PLAN`(입구 전용 표) — 층별 화면의 `SECTION_PLAN`·펼침
  예산 4와 **섞지 않는다**(섞으면 한 예산이 두 화면에 나뉘어 층별 카드 자리가 조용히
  줄어든다). 가드 시험이 두 표의 키 비겹침을 지킨다.
- 자료 0건·함수 부재(PGRST202)·조회 실패면 **카드 자체를 조용히 생략**(0건 카드 금지).

## 결정 3 — 마감 지난 공고는 화면에서만 숨기고 창고 보관

지우면 가벼워지지만 "어느 지역에 LH 상가 공급이 잦은가"라는 흐름 자료를 잃는다.
서버 함수가 `close_date >= 오늘` 만 반환하고, 표에는 남긴다(⛔ 수집기에 삭제 경로 없음).
