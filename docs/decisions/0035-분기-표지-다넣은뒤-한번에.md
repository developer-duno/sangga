## 무엇이 문제였나

화면은 창고(DB)의 **가장 새 분기**를 바로 보여 준다 — `snapshot_ym = (select max(snapshot_ym) from unit_business)`. 그런데 분기 적재기 `scripts/collectors/load_sangkwon_snapshot.py` 는 한 트랜잭션이 아니다: 시·도 파일마다 1,000행씩(`:107`) 차례로 올리고 약 2시간 걸린다(결정 0005). 첫 1,000행이 들어가는 순간부터 `max(snapshot_ym)` 은 새 분기를 가리키고, 그 2시간 동안 손님은 **반쯤 찬 새 분기**(대부분 건물의 가게 칸이 빔)를 본다. 적재가 중간에 죽으면 그 반쪽이 **그대로 남는다**(append-only 라 지우지도 않는다). 2026-10-06 (8) 마무리 맹점 검사관이 짚었다.

## 결정 (👤 사장님 결재 2026-10-06)

1. **'다 넣은 뒤 한 번에'** — 적재 중에는 화면이 전혀 안 바뀌고, 다 들어오고 확인이 끝난 뒤에만 바뀐다(저녁).
2. **표지는 두 칸** — '다 들어온 분기'(`loaded_ym`)와 '지금 보여 주는 분기'(`published_ym`)를 따로 둔다. 요약표는 앞 칸으로 굽고 화면은 뒤 칸만 본다 → 뒤 칸을 올리는 UPDATE 한 줄에 **모든 카드가 한순간에** 바뀐다. 적재가 중간에 죽거나 post_load 를 잘못 돌려도 아무것도 안 샌다(밤 23:2x).
3. **올리는 일은 `post_load.py` 가 자동으로** — 어차피 적재 뒤 꼭 돌리는 명령이라 단계가 안 는다. 따로 명령(`publish_snapshot.py`)은 **되돌리기·확인 전용**(밤 23:2x).
4. **라이브 적용 뒤 예행연습 한다** — 한가한 시간에 표지를 202603 으로 내렸다 202606 으로 되올려 '되돌리기'와 '한순간 전환'을 실제 데이터로 본다(밤 23:3x · 연습 동안 화면이 202603 을 말한다 — 요약표 굽기 두 번 ≈ 10분 안팎).

## 설계

### 표 `snapshot_release` — 한 줄짜리 표지판

```
id            int primary key default 1 check (id = 1)   -- 한 줄만 (0줄이면 화면 가게 칸이 조용히 빈다 → --check 가 [사고])
loaded_ym     char(6) not null   -- 다 들어온 분기(YYYYMM). 적재기가 전국 적재 + 교차검증 통과 뒤 RPC 로 적는다. 앞으로만.
loaded_at     timestamptz not null default now()
loaded_rows   int                -- 그때 센 그 분기 행 수(교차검증 값) — --check 가 지금 행 수와 대조
published_ym  char(6) not null   -- 화면이 보는 분기. post_load 가 요약표를 loaded_ym 으로 구운 뒤 올린다.
published_at  timestamptz not null default now()
```
RLS 켬 + `revoke all … from public, anon, authenticated`(정책 0). 첫 줄 = `(1, '202606', now(), 2772484, '202606', now())` → **적용 직후 화면은 그대로**다.

### 읽는 쪽 — 전부 표지만 본다

| 자리 | 바꾸는 식 |
|---|---|
| 실시간 3(`v_floor_stack` · `list_district_buildings` · `get_data_freshness` basis) | `(select r.published_ym from snapshot_release r)` |
| 요약표 3(`mv_parcel_store_names` latest · `mv_coverage_stats` where · `mv_district_industry_mix` where) | `(select r.loaded_ym from snapshot_release r)` — ⛔ **published 가 아니다**: post_load 가 새 분기로 먼저 굽고 나서 published 를 올려야 '한순간'이 된다 |
| 2순위 4줄(`list_industry_*` snap) | `coalesce((select max(m.snapshot_ym) from mv_district_industry_mix m), (select r.published_ym from snapshot_release r))` — "두 블록은 같은 분기, 정본은 요약표" 원칙 그대로 |

- ⛔ **함수가 아니라 스칼라 하위질의**로 읽는다 — 뷰 안에서 부르는 함수는 anon 권한으로 검사돼 열어야 한다(알려진한계 §4 · 2026-08-13 `building_display_nm` 사고). 하위질의는 InitPlan 으로 한 번만 계산돼 지금 `max()` 와 같은 모양이다(`mv_parcel_store_names` 주석 :1210 의 색인 조건도 그대로).
- 바뀌는 것은 **분기를 고르는 한 줄뿐** — 열·정렬·권한·색인 이름 전부 그대로(정본 `schema.sql` 도 같은 줄만).

### RPC `api.mark_snapshot_loaded(p_ym text, p_rows int) returns jsonb`

- security definer · `set search_path = ''` · **revoke from public, anon, authenticated · grant execute to service_role 만**(공개 호출 허용 28 그대로 — `post_load.py --check` 의 허용 목록에 넣지 않는다).
- 하는 일: `p_ym ~ '^\d{6}$'` 아니면 에러 · `unit_business` 에 그 분기 행이 0 이면 에러 · `p_ym <= loaded_ym` 이면 **아무것도 안 하고** 현재 표지를 돌려준다(앞으로만 — loaded ≥ published 가 늘 성립 · 2026-10-07 구현 때 published → loaded 로 좁힘)(같은 분기 재실행·옛 분기 백필) · 아니면 `loaded_ym = p_ym, loaded_at = now(), loaded_rows = p_rows` → 바뀐 줄을 jsonb 로.
- 적재기(`load_sangkwon_snapshot.py`)는 **`--sigungu-code all` + REST 교차검증 일치 + dry-run 아님** 일 때만 끝에 호출한다(`POST /rest/v1/rpc/mark_snapshot_loaded` · service 키). 아니면 "표지는 안 올렸습니다(전국 적재가 아니라서) — 올리려면 `python scripts/publish_snapshot.py --loaded <분기>`" 한 줄. **2026-10-07 보탬**: 전국 모드여도 건너뛴 시·도 파일(빈 파일·칸 빠짐)이 있거나 처리한 csv 수 ≠ 폴더 csv 수 ≠ 기대 시·도 파일 수(`EXPECTED_SIDO_FILES = 16` — 202606 폴더 실측 · 광주+전남 통합 뒤)면 RPC 를 부르지 않고 "빠진 파일 N개" + `--loaded` 안내 + exit 1(적대 검사관 🟠① — 교차검증은 "훑은 것 = 들어간 것"만 봐서 빠진 시·도를 못 잡는다). ⛔ 복구 안내는 `--ym` 이 아니라 `--loaded` 다 — `--ym` 은 보여 주는 분기를 바로 바꿔 post_load 의 굽기·확인을 건너뛴다(맹점 검사관 🟠2).

### `scripts/post_load.py` — 굽고, 확인하고, 올린다

```
표지 선점검(0줄·보여 주는 분기 0행이면 굽지 않고 exit 1 · 표지 없이 들어온 새 분기가 있으면 [경고] 뒤 끝에 exit 1)
→  vacuum (analyze)  →  분기와 무관한 요약표 5개 refresh(문장마다 자동커밋)  →  그 판정 넷(검색·지도·실거래 창·이웃 표 — 낡으면 여기서 exit 1)
→  ★ 한 파일 한 트랜잭션:
     set statement_timeout = '600s';  begin;
     refresh … concurrently mv_parcel_store_names / mv_coverage_stats / mv_district_industry_mix;   -- loaded_ym 으로 굽는다
     do $$ 표지 줄 for update 로 loaded 를 읽고 → 셋의 분기 = loaded 아니면 raise(통째 롤백)
           → update snapshot_release set published_ym = <그 값>, published_at = now() where id = 1 and published_ym < <그 값> $$;
     commit;   -- ★ 이 커밋 순간에 요약표 셋과 표지가 함께 바뀐다("표지 올림 202606 → 202609")
→  다시 잰다(분기 판정 셋 = 가게 이름·각주·업종 + 표지)
```
**구현에서 바뀐 것(2026-10-07 검사관 지적 뒤 · 👤 (가)안)**: 처음 구현은 요약표 8개를 `dbx.run_sql`(psql `-f` — begin/commit 이 없으면 **문장마다 자동커밋**)로 하나씩 굽고, 판정 6종이 끝난 뒤 따로 UPDATE 했다. 그러면 가게 이름 검색·각주·업종 카드가 1~2분 먼저 새 분기를 말하고, 판정 하나가 걸리면 그 창이 누가 고칠 때까지 남았다(맹점 검사관 🟠1). 그래서 분기와 묶인 셋과 표지 올림을 한 트랜잭션으로 묶었다 — 커밋 전엔 다른 세션이 옛 요약표·옛 표지를 보고 읽기가 막히지 않으며(로컬 PostgreSQL 18.4 실측 · 읽기 지연 0.02초), `refresh … concurrently` 는 트랜잭션 블록 안에서 된다(공식 문서에 금지 문구는 CREATE INDEX CONCURRENTLY 쪽에만 있다). DO 가 표지 줄을 `for update` 로 잡으므로 적재기 RPC(역시 `for update`)는 이 트랜잭션이 끝날 때까지 기다린다. 가게 이름 요약표의 분기(`store_snapshot_ym`) 대조도 판정에 넣었다(일곱 번째 · `--check` 에도).

`--check` 에 넷을 더한다(DB 쓰기 0):
| 점검 | 판정 |
|---|---|
| 표지 표가 0줄 / `published_ym` 분기가 점포 표에 없음 | **[사고] exit 1** — 화면 가게 칸이 통째로 빈 상태 |
| `loaded_ym ≠ published_ym` | **[낡음] exit 1** — 구웠는데 안 올렸거나 post_load 를 안 돌림 → "python scripts/post_load.py 를 돌리면 올라갑니다" |
| `max(unit_business.snapshot_ym) > loaded_ym` | **[주의]**(종료 코드 무관) — 적재 중이거나 적재기가 exit 1 로 끝남 · "적재기가 exit 1 로 끝났으면 … `publish_snapshot.py --loaded <분기>` 하고 post_load"(2026-10-07 — 본 실행에서는 같은 상태가 [경고] + 끝에 exit 1) |
| `loaded_rows ≠ count(그 분기)` | **[주의]** — 행이 더 들어왔거나 적게 들어옴 |

### `scripts/publish_snapshot.py` — 되돌리기·확인 전용

- `--show`: 두 칸·시각·행수 + 점포 표의 분기별 행 수 + 요약표 셋의 분기.
- `--ym 202606`: 두 칸을 **모두** 그 분기로(분기가 점포 표에 있어야 함) → "이어서 `python scripts/post_load.py`"(요약표를 그 분기로 다시 굽는다 — 올리는 UPDATE 는 no-op). dbx 경유(psql) · 평소엔 안 쓴다. **되돌리기 전용.**
- `--loaded 202609`(2026-10-07 신설 · 맹점 검사관 🟠2): `loaded_ym`·`loaded_at`·`loaded_rows`(그 자리에서 센 행 수)만 적고 **published 는 안 건드린다** — 적재기가 표지를 못 올렸을 때(RPC 실패·빠진 시·도 파일·시도 모드)의 복구 길. 점포 표에 그 분기 행이 0 이면 거부 · 지금 보여 주는 분기보다 옛 분기면 거부("뒤로는 --ym") · 끝에 "이어서 `python scripts/post_load.py`".

### 마이그레이션 `supabase/migrations/2026-10-07a_snapshot_release.sql` (파일 이름 날짜 = 만든 날)

## 하지 않는 것 (이유와 함께)

- **지역별 분기** — `v_floor_stack` 이 전역 한 분기를 보는 결함(알려진한계 §5)은 그대로다. 이 결정은 "어느 분기를 보나"를 `max()` 에서 표지로 바꿀 뿐, 지역마다 다른 분기는 다루지 않는다(1단계 서비스 범위 서울+대전이 같은 분기로 들어온다).
- **화면에 '적재됐지만 아직 안 보이는 분기' 표시** — 손님에게는 published 만 사실이다. 그 상태는 `--check`·`--show` 가 사람에게만 말한다.
- **적재기를 한 트랜잭션으로** — 270만 행을 한 트랜잭션에 넣으면 WAL·잠금이 커지고 REST 1,000행 묶음 구조를 통째로 바꿔야 한다. 표지가 같은 효과를 더 싸게 낸다.
- **요약표를 '두 분기 보관'으로** — 가게 이름 표가 두 배(176MB)가 되고 유일 색인 열쇠가 바뀐다. 표지 두 칸이면 필요 없다.
