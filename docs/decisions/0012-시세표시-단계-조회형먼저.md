# 0012. 층별 화면 시세 표시는 두 단계 — Stage A 사실 표시(즉시), Stage B 추정 밴드(백테스트 후)

날짜: 2026-08-15 / 상태: 확정 (사장님 위임 — "미래가치와 실증을 근거로" Claude 결정) / Phase 3 입구

## 1. 실측이 정한 제약 (2026-08-15, 실거래 서울+대전 24개월 적재 직후)

- 화면 건물 필지 중 **자기 실거래(지번 공개 구간 202401+)가 있는 곳은 서울 1.8%
  (2,799/156,349) · 대전 1.4%(457/32,093)** — "이 건물 이력"만으로는 98% 건물이 빈칸.
- (필지, 층) 표본 2건 이상 조합은 2,609개뿐 — 같은 건물·같은 층 밴드는 희귀.
- PNU 있는 거래 중 층 정보 보유 54.2%(10,216/18,852).
- 절대 규칙: "적정가격" 금지(2) · 신뢰도 배지=근거+표본 수(3) · 확정 설계 6
  "조회형 먼저 — 추정 검증 전 추천 금지".

## 2. 결정

### Stage A — 사실만 표시 (추정 0, 즉시 구현)

층별 스택 화면에 두 가지를 추가한다. 둘 다 실측 집계라 규칙 리스크 0.

1. **이 건물(필지)의 실거래 이력** — 있는 경우만. 층·계약년월·전용면적·금액·단가(원/㎡)·
   거래유형 그대로. 층별 스택의 해당 층에 건수 뱃지.
2. **구(시군구) 실거래 단가 통계** — 항상 표시. 최근 24개월 **집합** 거래를
   층대(지하/1층/2층/3층+/층미상)로 갈라 중앙값·25~75% 범위 + **표본 수 병기**.
   표본 5건 미만인 층대는 수치 대신 "표본 부족"(검증 규칙의 미표시 원칙).

- 지역 단위는 **구로 시작**한다. 실거래의 동 이름(문자)과 건물의 법정동 코드는 다른
  체계라 이름 대조가 깨지기 쉽다 — 법정동 확장은 표본·매핑 검증 후의 경로로만 남긴다.
- 일반(통건물) 거래는 PNU 가 없어(알려진한계 — 마스킹 100%) 건물 이력에는 못 붙는다.
  구 통계에는 집합만 쓴다(면적당 단가의 성격이 달라 섞으면 분포가 오염된다).

### Stage B — 참고 시세 밴드 (추정, 선행조건 통과 후 재결재)

반경 500m 동일층 사다리(§6.2) 기반 "3.2억~3.8억 (표본 7건)" 형태. 선행조건:
① 시간 분할 백테스트를 **서울 전역+대전**으로 재실측(기존 성적은 강남뿐) ② 지역·층별
오차 성적표에서 기준 초과 지역은 "표본 부족"만 표시 ③ 신뢰등급 A~D 시각 구분.
성적표가 나오면 그 숫자를 들고 다시 결정한다. **Stage B 전에는 어떤 추정값도 화면에
내지 않는다.**

## 3. 구현 형태 (Stage A)

- DB: 함수 `list_parcel_transactions(pnu)`(개별 이력) · 사전계산 `mv_sigungu_tx_stats`
  (구×층대, post_load 갱신 편입) + 래퍼 함수 `get_sigungu_tx_stats(sigungu)`.
  ⚠️ matview 는 anon 에 직접 열지 않는다(2026-08-13 사고 답습) — 함수만 연다.
  노출 허용 목록(post_load)·schema.sql grant·드리프트 가드 동기.
- 화면: FloorStack 에 "실거래" 섹션 + 층 뱃지. 문구에 "적정/평가" 계열 금지,
  항상 "실거래 N건 기준" 병기.
