## 선택지와 판단 (사장님께 드린 근거 그대로)

| 선택 | 지금 가치 | 로그인이 생기는 날 | 판정 |
|---|---|---|---|
| **A 종류 고르기 + 숨김 칸** ✅ | 쌓이는 자료의 품질 ↑ | 그대로 씀 | **채택** |
| B 공개 "고쳤습니다"(저장소 파일) | 0건이라 빈 목록 | 그대로 씀 | 첫 "고친 일"이 생기면 그때 |
| C 이메일 칸·손 답장·1년 | 답장 가능 · 개인정보 의무 발생 | 이메일 칸·처리방침을 걷어내야 함 | 두 번 짓고 허뭄 |
| D 안 함 | 0 | 종류 없는 자료가 쌓임 | 미래 자료 품질 손해 |

- **왜 C 가 아닌가**: 결정 0003 §8 이 "회원은 생기는 시점에"라고 이미 적어 뒀다. 로그인이 생기면 2u
  처럼 **답장은 가입 이메일로** 가므로 이메일 칸이 필요 없어진다. 지금 파면 그날 메워야 하는 임시 벽이다.
  최상위 방침(2026-08-19 "가입 유도·문의 강요 금지")과도 결이 다르다. 0016 이 적어 둔 반대편(사장님은
  공인중개사 — 관심이 가장 높은 순간의 손님과 연락할 길이 없다)은 실재하지만, 회원이 생기는 날 자연히
  풀리는 기회비용이라 지금 임시로 메울 이유가 약하다.
- **왜 지금 병목이 의견함이 아닌가**: 0건은 우편함이 나빠서가 아니라 아직 손님이 없어서다. 기능을 더
  붙여도 편지는 안 는다. 대신 편지가 오기 시작할 때 **종류별로 나뉘어 쌓여 있어야** "무엇을 먼저
  만들지"를 정하는 자료가 된다 — 종류 고르기는 그 미래 자료의 품질을 지금부터 올리는 유일한 항목이다.
- **왜 B 는 미루나**: 신뢰 신호로 값어치가 있지만 올릴 내용이 0건이라 빈 목록으로 시작하게 되고, 빈
  목록은 "아무도 안 쓰는 서비스"라는 반대 신호다. 저장소 파일 하나라 첫 번째 고친 일이 생기는 날
  반나절이면 붙는다.

## 어떻게 만들었나

| 조각 | 자리 |
|---|---|
| 종류 표(키·글자 한 곳) | `src/lib/feedback.ts` `FEEDBACK_CATEGORIES` — `bug` 버그·오류 / `data` 정보가 틀려요 / `suggest` 건의·제안 / `other` 기타(문구는 2u 에서 사장님이 정한 것을 재사용) |
| 고르기 UI | `src/components/FeedbackBox.tsx` — 라디오 4개, **기본 선택 없음**(다 '기타'로 남는 걸 막는다), 안 고르면 보내기 잠김 |
| 싣는 자리 | `context.category` — 서버 `kind`(opinion/error)와 CHECK 제약은 **그대로**(마이그레이션 0 · 공개 허용 목록 변화 0) |
| 봇 숨김 칸 | 보이지 않는 글 칸 하나 — 값이 있으면 보내지 않고 "고맙습니다"만 띄운다 |

⛔ **숨김 칸은 반쪽이다.** 서버가 없어 검사가 브라우저에서 돈다 — 화면 폼을 긁는 봇은 막지만 창고
함수를 직접 부르는 봇은 못 막는다. 그쪽은 이미 있는 창고 쪽 상한(분당 60 · 하루 1,000)이 진짜 방어다.
비밀번호 관리 프로그램이 숨김 칸을 채울 수 있다는 2u 의 함정은 `autoComplete="off"` 와 낯선 이름으로
줄였을 뿐 0 은 아니다(2u 도 아직 🟡).
