## 2. 왜 react-kakao-maps-sdk 인가

| 후보 | 카카오맵 연동 | React 19 | 판정 |
|---|---|---|---|
| **react-kakao-maps-sdk** | **전용 래퍼** | **공식 지원** (321★, 유지보수 활발 — 2026-08-14 GitHub 실측) | ★ **채택** |
| deck.gl | **공식 연동 없음** | 지원 | **탈락** — 카카오맵과 겹쳐 그리려면 좌표계·카메라 동기화를 우리가 직접 짜야 한다 |
| 카카오맵 JS SDK 직접 호출 | 당연히 됨 | 해당 없음 | 차선 — 되지만 React 생명주기(마운트·언마운트) 관리를 손으로 해야 해 누수가 나기 쉽다 |

**결정적인 이유**: 우리 지도는 **이미 카카오맵**이다(CLAUDE.md 아키텍처). 여기서 deck.gl 을
고르면 "지도 한 장에 렌더러 둘"이 되고, 확대·이동할 때 두 그림이 어긋나지 않게 맞추는 일을
평생 떠안는다. 1,687개 면은 deck.gl 의 GPU 가속이 필요할 규모가 전혀 아니다.

> ⚠️ deck.gl 을 영영 안 쓴다는 뜻은 아니다. 호실 수백만 개를 점으로 뿌리는 화면이
> 생기면 그때 다시 본다 — **지금 상권 면에는 과하다**는 판단이다.

## 3. 왜 조회가 아니라 파일인가 (그리고 크기 실측)

CLAUDE.md 성능 원칙: **"상권(수천 개)은 사전계산 정적 JSON, 호실(수백만)은 쿼리."**
상권은 1,687개뿐이고 **거의 안 변한다**(원본 자체가 비정기 갱신 — 0008 §8·0009 §3).
지도를 열 때마다 1,687개 면을 DB 에서 뽑으면 느리기만 하고 얻는 게 없다.

**단순화 실측 (2026-08-14, 라이브 1,687행)**

| 단계 | 크기 |
|---|---|
| 원본 도형 그대로 | **4.98MB** |
| `ST_SimplifyPreserveTopology(geom, 0.0001)` + 좌표 6자리 | **0.76MB** |
| 최종 파일(속성·구조 포함) | **1.13MB** (1,188,309 bytes) |

- `0.0001°` ≈ **11m**, 좌표 소수 6자리 ≈ **11cm**. 상권 하나가 화면에서 몇 백 픽셀인데
  그보다 잘게 그려 봐야 눈에 안 보이고 첫 로딩만 무거워진다.
- ⛔ **`ST_Simplify` 가 아니라 `ST_SimplifyPreserveTopology`** 다. 앞의 것은 점을 솎다가
  면을 **스스로 교차시켜** 깨뜨린다 — 지도에 리본처럼 꼬인 그림이 나오거나 아예 안 그려지는데
  **에러가 아니라서** 눈으로 찾기 어렵다. 실측: 단순화 뒤 NULL 0개 · `ST_IsValid` 실패 **0개**.
- 결과 구성: Polygon 1,598 · MultiPolygon 89 / 유형 5종(골목 1,090 · 전통시장 305 ·
  발달 249 · 주요 37 · 관광특구 6) / 출처 2종(서울시 1,650 · 소진공 37).

**diff 노이즈를 안 만든다**: 파일에 "만든 시각"을 적지 않는다. 적으면 자료가 하나도 안
바뀌었는데 다시 구울 때마다 파일이 달라져 git 이 매번 1.1MB 변경으로 본다. 정렬도 DB 가
아니라 파이썬이 한다(`면적 내림차순, 같으면 district_id`) — DB 의 문자열 정렬 규칙은 서버
설정에 따라 달라질 수 있어서다. **실측: 두 번 구워 md5 동일.**

## 4. 신선도는 등식으로 잡는다 (`post_load --check` 편입)

정적 파일의 유일한 위험은 **"상권을 새로 적재하고 파일 굽기를 잊는 것"**이다. 그러면
검색도 층별 화면도 멀쩡한데 **지도만** 옛날 상권을 보여준다 — 에러가 안 나서 아무도 모른다.

그래서 파일 맨 위에 `meta` 를 박아 두고 라이브와 대조한다:

```
파일 meta.district_cnt    == select count(*) from district
파일 meta.max_computed_at == select max(computed_at) from district   (UTC 로 고정 렌더링)
```

추측이 아니라 **반드시 성립해야 하는 등식**이다(post_load.py 의 검색 요약표 검사와 같은 정신).
`python scripts/post_load.py --check` 가 이제 **세 줄**을 찍는다 — 요약표 · **지도 파일** · 권한.
하나라도 어긋나면 종료 코드 **1**.

> ⚠️ 시각은 **UTC 로 못박아** 찍는다. `computed_at::text` 로 두면 접속 세션의 시간대 설정에
> 따라 `+00` 이 `+09` 로 렌더링돼, 자료가 그대로인데도 등식이 어긋난다(굽는 사람과 검사하는
> 사람의 환경이 다를 때 바로 터진다).

**⚠️ `post_load.py` 는 파일을 자동으로 굽지 않는다.** 그 파일은 **git 에 커밋하는 자산**이라
사람이 보고 커밋해야 한다. 자동으로 구우면 커밋 안 된 생성물이 워킹트리에 조용히 쌓인다.
그래서 "낡았다"고 알리고 명령만 안내한다.

## 6. 카카오 지도 키 운영 조건 (2026-08-14 확인)

- **도메인 등록 필수** — 등록 안 된 도메인에서는 지도가 안 뜬다. 배포 도메인을 카카오
  개발자 콘솔에 미리 넣어야 한다.
- **localhost 공식 지원** — 개발용으로 따로 우회할 필요 없다.
- **일 30만 건 무료**, 초과분 건당 0.1원. 우리 규모에서 한도가 문제 될 상황은 아니지만,
  키가 도메인에 묶여 있으므로 **새 도메인을 열 때 등록을 잊으면 지도만 빈 화면**이 된다.

## 7. 출처 표기 (공공누리 1유형 의무)

두 소스 다 **공공누리 1유형/이용허락 제한없음**이라 상업적 이용은 되지만 **출처 표기는 의무**다.
화면에 고정 문구를 박지 않고 **`source_nm` 칸을 자료에서 읽어** 보여준다 — 소스가 둘이 된
순간(서울시 / 소진공) 고정 문구는 한쪽에 거짓말이 되기 때문이다(결정 0009 §1-③에서 이미
정한 규칙을 지도에도 그대로 적용). 그래서 `source_nm` 은 geojson 속성에서 **뺄 수 없다**.
