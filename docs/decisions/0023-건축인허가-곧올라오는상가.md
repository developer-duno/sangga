## 무엇이 문제였나

건축물대장은 **완공된 뒤에야** 생긴다. "이 둘레에 새 상가 건물이 올라오는 중"이라는 공급
신호 — 창업자에겐 경쟁 예고, 투자자에겐 공급 예고 — 를 보여줄 길이 없었다. 건축인허가
API 는 8-07 에 이미 승인돼 있었고 8-19 조사가 가치(상업지 필지 매칭 86.1%)와 함정을
확인해 뒀지만, 화면 자리와 수집 방식이 정해지지 않아 잠들어 있었다.

## 결정 0 (조사에서 확정) — **API 가 아니라 일괄 파일로 받는다**

| 후보 | 판단 |
|---|---|
| API 전수 훑기 | ❌ 날짜 거름 인자가 없어 매월 5천~1만 콜 — 대장의 "211일 문제"와 같은 결 |
| 화면에서 온디맨드 호출 | ❌ **서버가 없는 구조라 브라우저에 API 열쇠가 통째로 노출**된다 |
| **건축HUB 일괄 파일** ✅ | 분류 01(인허가)에 `0101 기본개요` **월간 438MB zip** 실재(2026-08-28 실측 — 로그인 불필요, 대장처럼 **최근 3개월만 보관**이라 받으면 원본 보관) |

## 결정 1 — 적재는 **미준공 + 2023년 이후 허가만** (전국 650만 행 중 556,527행)

매월 통째로 재적재하는 자료라 가볍게 유지한다(연 1회짜리 기준시가의 "전국 한 방"과 전제가
다름). 원본 zip 은 `data/raw/arch_permit/<기준월>/` 에 통째 보관(3개월 보관 제약 대비).
재적재는 기준월(loaded_ym) 단위 delete → insert — 그래서 **PK 는 (관리번호, 기준월) 두 칸**
(한 칸이면 다음 달 적재가 통째로 실패한다 — 구현 중 실측).

2026-07 판 실측: 전국 6,498,901행 → 준공 제외 −330만 · 2023 미만 제외 −264만 →
**556,527행**(그중 실착공 61,330). PNU 조립률 **99.959%**(대지구분 코드 어긋남(0↔1·1↔2)은
대장 변환기 선례 재사용).

## 결정 2 — 화면은 **둘레의 업종 분포 카드 안 한 줄** (새 카드 없음)

> 둘레에 **새로 올라오는 상가 건물 N동** — 허가만 O동 · 착공 P동 (2026년 7월 인허가 기준).
> 허가를 받았다고 모두 지어지는 것은 아닙니다.

- 반경은 기존 업종 분포와 **같은 이웃 필지 장치**를 재사용(새 발명 0).
- **상업 계열 = 주용도 코드 앞 두 글자 03(근생1)·04(근생2)·07(판매)·14(업무)** —
  실측 분포(각 24,952·39,882·1,617·5,967 = 72,419곳)에 근거. 숙박(15)·위락(16)·공장(17)·
  창고(18)·주택(01·02)은 상가 축이 아니라 제외.
- ⚠️ **주용도 빈 값이 적재분의 70%(389,822행)** — 열면 화면 숫자가 대여섯 배로 부풀어
  제외했다. 따라서 이 셈은 **하한**이다(알려진한계 §3 등재). 앞일 단정("예정·곧 완공") 없이
  기준월 사실 서술 + 한계 부기로 끝낸다.
- 0동·함수 부재·조회 실패 → 줄만 조용히 생략.

## 결정 3 — 갱신은 **월 1회 수동 + 명령표 기록** (감시 그물 추가 없음)

대장 일괄 파일과 같은 리듬. 매월: `fetch --kind permit-basis` → `load_arch_permits.py`
→ `post_load.py` → `backup_raw.py`.

## 구현 중 실측이 잡은 함정 (재발 방지 박제)

1. **관리번호가 22자리** — bigint(19자리 상한)를 넘는 행이 79만. `text` 로 담는다.
2. **허가일을 글자로 비교하면 안 된다** — `'9902' >= '20230101'` 이 참이라 1990년대 행이
   "최근"으로 둔갑(24행 실측). date 변환 후 비교, 회귀시험 있음.
3. 원본 날짜 쓰레기(`'1999'`·`'1995 530'`)가 실재 — "담기로 한 행 안"의 이상 날짜만 롤백
   대상으로 좁혔다(전면 적용하면 정상 파일이 영영 안 들어옴). 기준월 이후 미래 허가일
   70행(원본 오타)은 버리지 않고 담는다.
